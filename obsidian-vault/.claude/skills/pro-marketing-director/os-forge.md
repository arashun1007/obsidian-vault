# os-forge.md — マーケOS正典の生成と維持

初回セットアップ（P1到達時）と四半期ごとの棚卸しで読む。このモジュールの成果物は、使用者専用の `MARKETING_OS.md`（正典）。以後すべての宣言（core.md §4）はこの正典に照らして裁く。

**P0（打席前）の使用者にはこのモジュールを適用しない**（core.md §3）。まず1つ売ってから戻ってくる。

## §1 生成インタビュー（初回60分）

正典は質問への回答から組み立てる。順序:

```
1. ポジショニング（positioning.md の三問。済みなら宣言を転記）
2. 商品ラダーの現状（offer-design.md §2 の5段に何があるか。ないものは「ない」と書く）
3. 販路の現状（place.md §1 の三軸裁定表を埋める）
4. チャネルの現状（§3 のチャネル方針表）
5. 自動化レベル監査（§2）
6. KPIツリー（§4）
7. やらないことリスト（§6）
8. 本人判断事項の分離（§7）
9. 改善ループの装填（§9。P1では最小形の予約だけでよい）
```

回答が「わからない」の項目は、埋めずに**「未調査」と明記**してresearch-protocol.mdの調査対象キューへ送る。わからない欄をそれらしく埋めるのは事実検品違反。

## §2 自動化レベル監査（L1/L2/L3/穴）

現状のマーケ作業をすべて4段に棚卸しする:

```
### L1: 全自動（cron等が回している）
| 機能 | 場所 | 備考（冪等性・二重実行防止など） |

### L2: 半自動（AIが起草→本人レビュー→反映）
- <人間の最終確認を要する作業>

### L3: 手動のみ
- <API未対応、または規約上・リスク上あえて自動化しない作業>

### 存在しない（穴）
- <未実装の機能を列挙。理由は問わず「ない」事実だけ>
```

- L2は「誰が起草し、誰が最終確認するか」を必ず併記する。**人間レビューを挟む半自動も正式な運用レベル**——「原稿は人・OSは増幅」と自動化推進を両立させる鍵。
- 監査時は信号色との突合を必ず行う（automation.md §2の上限則: Green→L1可／Yellow→L2止まり／Red→L3固定）。L1にYellow項目が混ざっていたら越権自動化として降格する。
- L3には「あえてやらない」も含める（やらないことリスト §6 と連動）。
- 「穴」の直後に**コンテンツ在庫の残量表**を置く。弾切れはエラーにならず「無音」になる（投稿が止まるだけで誰も気づかない）ため、残量監視自体を自動化タスクとして切り出す。
- 監査は日付つきスナップショットとして残し、次回は上書きでなく更新履歴が追える形にする。

## §3 チャネル方針表

```
| チャネル | 規模 | 役割（新規獲得/再接触/教育/ストック） | 自動化の関与度（計測のみ/半自動/全自動） |
```

- 「役割」列で各チャネルの戦略上の位置づけを一語で言い切る。役割が書けないチャネルは撤退候補。
- 全チャネルを埋める必要はない。**空欄の多い表は健全**（一点集中。core.md §3）。

## §4 KPIツリー

```
北極星（現フェーズ）: <単一の最重要指標>
北極星（次フェーズ）: <次段階の指標。フェーズが変われば北極星も変わってよい>

集客: <指標>（実装済/未計測） / ...
転換: <登録CVR等>（計測イベント名を併記） / ...
継続: <継続率・解約率> / ...
拡散: <紹介成立数・共有数> / ...
収益: <売上・LTV>（前提条件があれば併記） / ...
```

- 各指標に**実装済み/未計測を必ず注記**する。「測ろうとしているが測れていない」ギャップの一覧が、計測投資の優先順位になる。
- 指標は許可リスト方式。意味を説明できる指標だけを載せ、無制限に増やさない。

### 計測の実装（2段構え）
- **フォールバック（全員必須）**: 週1回、手で数字を写す「週次手動計測」。テンプレ: 日付・北極星・各カテゴリ1指標ずつ・一言所見。ツールがなくても正典は運用できる。
- **自動化（P2以降）**: 計測と改善は「接続→観測→気づき→提案→承認→実験→採用/巻き戻し→判断ログ」の自動運転パイプラインに載せ替える。設計の詳細（3パイプライン・信号色・5つの台帳・実験の安全ルール）は automation.md、運転手順は kaizen.md。

## §5 事実台帳

商品・実績に関する**使ってよい事実の正典**を1ファイルにまとめる（例: `OFFER_FACTS.md`）。価格・受講者数・実績・証言はここに登録されたものだけをコピー・オファー・LPに使える（事実検品の照合先）。出典と登録日を添える。

## §6 やらないことリスト

```
| 施策 | 理由 |
|---|---|
| <規約グレーの自動化> | <該当規約名・過去の実例> |
| <有料広告 等の方針判断> | <方針と代替手段> |
```

- 目的は、**同じ提案が再浮上したとき毎回ゼロから検討し直さない**こと。KPI宣言の照合先として機能する。
- 理由は抽象論でなく、規約の条項名・過去の実例など**具体的な参照点**を書く。理由のない禁止は将来緩められて事故になる。

## §7 決定ログと本人判断事項

- **決定ログ**: 「回答済み（日付・意思決定者）」という確定状態で書く。実装が伴う決定は「→ 前提・担当」を続けてタスク化する。保留も消さずに残す。
- **本人判断事項の分離**: 金銭・経済バランス／新チャネル開設の温度感／法務グレーの最終ゴーサイン、はAIに委任せず独立セクションに切り出す。実行ロードマップに「本人が決めないと動けない項目」を混ぜると、ブロックされたまま放置される。
- 宣言（戦略宣言/KPI宣言）はすべて決定ログに転記する。**「勘で当たった/調査して外れた」の蓄積が、この正典の最も価値ある資産になる。**

## §8 維持の掟

- 正典は四半期ごとに棚卸しする（§2の監査を更新・KPIツリーの実装状況を更新・やらないことリストの理由の鮮度確認）。月次の軽い同期は kaizen.md §4（Loop 2）が受け持つ——四半期棚卸しはその上位互換で、正典全体を見直す。
- 正典と現実がずれたら、現実に合わせて正典を直す。正典に書いてあるだけで運用されていない項目は「穴」に降格する。

## §9 改善ループの装填（P2、またはP1で計測が回り始めたら）

改善ループ（kaizen.md）が物理的に回るための置き場を、OS生成の仕事として作る。**概念のままの台帳には、AIも人間も書き込めない。**

- **5台帳（automation.md §3）を実ファイルとして生成する。** 推奨: 正典と同じ場所に `ledgers/` を切り、接続=`CONNECTIONS.md`／指標=`METRICS.md`／導線=`FUNNEL_TRACE.md`／提案=`PROPOSALS.md`（proposed→approved→observing→adopted/rolled-back の状態遷移をここで管理。実験台帳を兼ねる）／判断ログ=`DECISIONS.md`（追記のみ）。空でよいから雛形と記入例を置く。
- **OS正典に「勝ちパターン集」セクションを空で作る**（月次Loop 2の昇格先。kaizen.md §4。「空欄=まだ2回再現した勝ちがない」という正直な状態表示になる）。
- **週次改善セッションの定期実行を設定する**（kaizen.md §5）。初回は必ず手動で1周し、生成物を検品してから定期実行に昇格する。
- P1でここまでの装備が過剰なら、kaizen.md §6 の最小形（数字＋提案3件＋裁定＋判断ログ1ファイル）で予約だけして先へ進む。
