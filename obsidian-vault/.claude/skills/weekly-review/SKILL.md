# weekly-review — 週次のネタ棚卸しとふりかえり

## 大原則

- **既存ファイルは読むだけ。編集・削除はしない。** 出力は新規ノート1つ（`01_daily/weekly/YYYY-Www_レビュー.md`）のみ。
- 日記には体調・気分の記録が含まれる。**この skill が扱うのは「発信ネタ」「仕事」「継続の仕組み」だけ**。メンタルヘルスの記録は集計・評価・言及しない（本人が明示的に頼んだ場合を除く）。
- 安易な肯定やポジティブ変換は禁止。事実ベースで淡々と。

## 手順

### 1. 読む
- `01_daily/` の直近7日分（「発信ネタ」「気づき」「印象に残った言葉」欄を中心に）
- `10_work/日報/` の直近7日分（作業種別・お客様の反応・AI生成用メモ）
- `30_publish/Substack/ネタストック.md`（現在の在庫）
- `30_publish/Substack/記事メトリクス.csv`（あれば。記事の反応記録）

ファイルが無い週でも止まらない。あるものだけで進め、無かったものは末尾に「今週は◯◯が未記入」と事実だけ書く。

### 2. 出力する（新規ノート1つ）

```
# YYYY-Www 週次レビュー

## 今週書いた記事と反応
（メトリクスCSVから。無ければ「記録なし」）

## 反応の傾向（3週以上データがある場合のみ）
どのテーマ分類（生活系/野生系/内省系）が読まれているか。事実だけ。

## 日記から拾った記事のタネ（5〜10個）
引用元の日付付き。原文の言葉のまま拾う（要約して潰さない）。

## ネタストック補充案
上のタネのうち、ネタストック.md に追記する価値があるもの。
→ 本人が承認したら追記する（勝手に追記しない）。

## 仕事まわりのメモ
今週の現場から、営業コンテンツ化（/work-content）できそうな日報。

## 来週の一手（最大3つ）
継続の仕組みに関わることだけ。小さく。
```

### 3. 提案して終わる
ネタストックへの追記、記事化する素材の選定は、提案して本人の承認を待つ。
