# review-protocol.md — 検品4種（出荷ゲート）

**公開物はすべて、公開前にこの4検品を通す。** 順序は 機械→文体→事実→リーガル（安いチェックから高いチェックへ。機械で落ちる原稿に人間の時間を使わない）。

このスキルの根本思想: 生成AIマーケの最大の信頼問題は「AIが嘘を書く・調子が狂う・法を知らない」こと。**書くAIではなく、書いて自分を検品するAI**であることが、このスキルの品質保証である。

## §1 機械検品（形式要件）

客観的に真偽判定できるものはすべてスクリプトで検査する。人間の目視は機械化できない仕事に取っておく。

```python
# 代表的な検査（python3ワンライナー群。対象ファイル全件に対して回す）
import pathlib, re
for f in sorted(pathlib.Path('content').glob('**/*.md')):
    t = f.read_text()
    body = re.sub(r'---.*?---', '', t, flags=re.S)                                  # frontmatter除去
    body = re.sub(r'https?://\S+|%\w+%|<!--.*?-->|[\w.]+@[\w.]+', '', body)         # URL/変数/コメント/メール除去
    if t.count('<!-- seg:') != t.count('<!-- /seg -->'): print(f.name, 'セグメントタグ不整合')
    if re.findall(r'[Ѐ-ӿ가-힯]+', body): print(f.name, '異言語文字混入(キリル/ハングル)')
    if '**' in body.replace('***',''): print(f.name, 'markdown太字疑い')
```

- **異言語混入は実際に起きる**（AI編集の副作用として複数回の実例あり）。簡体字は上の正規表現レンジで拾えないため、簡体字専用の文字リストで別途スキャンする。リストに日本語常用字を混ぜない（誤検知の源）。
- そのほかの定番: 文字数上限（媒体別の換算式: 全角2・半角1・URL固定値）・必須要素の有無（フッター・署名・frontmatter）・禁止語（文体正典のgrep。blog.md §2）・口癖密度の閾値（mail.md §3）。
- **Markdown事故はレンダリング後の実物で検査する**: 改行をまたいだ`**`強調・括弧に外接する太字は、ソース上は正しく見えてもレンダリングで生の`**`が露出する。書き終えたら**レンダリング後の可視テキスト**に`**`が残っていないかを機械検査する。この種の露出は「AI感」の最大源であり、読者の信頼を一撃で削る（実例複数）。
- 検査は**ストック全件**に回す。新ルール追加時に過去分も一括検査できる。
- 検査を騙さない: ユーモアとして異言語や禁止記法をわざと混ぜる書き方をしない。事故と見分けがつかなくなり、検品自体が汚染される。

## §2 文体検品（人間レビューとの役割分担）

- **機械=形式要件、人間=内容とトーン。** 「詩的でよい」のような感性的ルールをテスト化しようとしない。逆に、検査可能なルール（禁止語・構成要素）を人間の目視に頼らない。
- チェック観点: 文体正典（blog.md §2）との一致 / 語り（情緒）と事務（事実）の分離——数量・条件・価格・URLは装飾のない箇条書きで言い切っているか / AI臭の三大源泉（定型句反復・均一リズム・無内容の丁寧さ。blog.md §3）。
- 修正は**外科的Editのみ**。検品で見つかった問題を「全文書き直し」で直すと、直した箇所以外に新しい事故を持ち込む（mail.md §3 の実測知見）。

## §3 事実検品（provenance照合）

- 原稿中のすべての実績・数字・証言・効果の主張を抜き出し、**事実台帳（os-forge.md §5）と照合する**。台帳にないものは (a)台帳に出典つきで登録してから使う (b)削る、の二択。「それらしいから残す」は無い。
- 年度・制度依存の数値が残っていないか（mail.md §4）。
- 第三者の実名・特定可能情報が匿名化されているか。
- 検品記録を残す: 照合した主張の一覧と判定。**不採用の判断も理由つきで残す**（同じ素材の再検討を防ぐ）。

## §4 リーガル検品

位置づけ: この検品は**適法性の保証ではなく事前選別**である。判定は3値——`通過`（機械的に問題なし）/ `要専門家確認`（人の判断・専門家の確認が必要）/ `ブロック`（明確な違反疑い。修正するまで出荷不可）。

- `ブロック`判定を「本人がOKと言ったから」で上書きしない。原稿を直した**新しい版**で再検品する。
- 微妙な項目を「問題なし」と人が判断した記録は、本文が変わったら失効させる。
- チェックリスト自体に鮮度がある。法改正の報道時と年1回、リストの根拠を再確認する（research-protocol.md §7）。

### 4.1 景品表示法（すべての訴求文）
- [ ] 効果・性能の表示に合理的根拠があるか（不実証広告規制）
- [ ] No.1表示・最上級表現（「最速」「業界初」等）に根拠があるか
- [ ] 体験談・証言の出所と代表性（例外的成功を一般的結果に見せていないか）
- [ ] 広告であることが判別可能か（ステマ規制。アフィリエイト・PR案件・紹介者の投稿も対象）
- [ ] 二重価格表示・割引率・「値上げ予定」表示に実態と根拠があるか
- [ ] 打消し表示（注釈）が明瞭に読めるか
- [ ] 在庫・期限・希少性の表示が実態と一致しているか（演出の「残りわずか」禁止）

### 4.2 特定商取引法（販売ページ・申込導線）
- [ ] 通信販売の法定表示事項（特商法表記ページ）が揃っており、LPから到達できるか
- [ ] 返品・キャンセル・解約条件が明示されているか
- [ ] 定期購入・無料体験の重要条件（次回請求日・金額・解約方法）が申込前に明瞭か
- [ ] 最終確認画面に法定表示があり、申込内容を訂正できる導線があるか
- [ ] 申込期間・カウントダウンが実態と一致しているか

### 4.3 特定電子メール法（メール配信）
- [ ] オプトイン（事前同意）または法定の例外要件を満たしているか。同意の証跡があるか
- [ ] 配信停止導線があり、停止後に送信が止まる仕組みがあるか
- [ ] 送信者の正式名称・住所・問い合わせ窓口が表示されているか

### 4.4 金融・暗号資産・NFT（該当事業のみ）
- [ ] 利益保証・元本保証・利回り訴求をしていないか
- [ ] トークン・NFTの法的分類を確認したか（前払式支払手段・集団投資スキーム該当性）
- [ ] 暗号資産の紹介が「媒介」に該当しないか。無登録業者の勧誘になっていないか
- [ ] 投資判断に影響する情報にリスク表示があるか

## §5 出荷判定

```
□ 機械検品: 検査スクリプト全通過（出力ゼロ）
□ 文体検品: 人間レビュー済み（外科的Editで修正済み）
□ 事実検品: 全主張が台帳と照合済み
□ リーガル検品: 全項目「通過」または「要専門家確認」の解消済み
→ 4つ揃って出荷。1つでも欠けたら出荷しない。
```

例外は下書き・非公開の社内文書のみ。「今回だけ急ぎで」が事故の定型文である。
