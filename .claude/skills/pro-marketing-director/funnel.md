# funnel.md — 導線設計（5層ファネルと三つのループ）

導線の設計・診断のとき、「商品はいいのに売れない」と感じたときに読む。前提: **導線なき良品は穴の開いたバケツ**（柱2）。

## §1 5層ファネル

```
認知   : 部族に見つけてもらう（x-ops / blog / video）
集客   : 見つけた人をリストにする（無料プレゼント → メール/LINE登録）
教育   : 価値提供で信頼を積む（mail のステップ配信。10〜20日）
販売   : オファーを出す（lp-sales）
定着   : 買った人を仲間にする（community）
```

- 各層の受け渡し点（認知→集客の登録導線、教育→販売のオファー）が「穴」の常習ポイント。
- **いきなり売らない**（柱4）。教育層を飛ばした販売は、部族でない人への売り込みになり、旗（positioning.md）を傷める。

## §2 三つのループ — ファネルは直線ではなく環

```
[集客ループ]  流入チャネル群 ──→ 受け皿（LP/プロフィール）
                   ↑                        │
[転換ループ]  拡散装置（紹介/シェア） ←── 登録 → フォローアップ
                   ↑                        │
[継続ループ]  共有/イベント ←── 商品・コミュニティ ←── 再訪トリガー
```

- 継続ループの末端（購入者の共有・紹介）が集客ループの先頭に戻る**環**として描く。環が閉じているビジネスは広告費なしで成長する。
- 各ループに**生死判定**（生きている/切れている）を添えると、次の施策の優先順位が自動的に決まる。「集客は生きているが転換が死んでいる」のような診断が、施策の乱発を防ぐ。

## §3 バケツ診断の手順

「売れない」相談を受けたら、感想を言う前にこの順で数字を見る:

```
1. 各層の数字を並べる: 認知(表示/再生) → 集客(登録数/CVR) → 教育(開封/クリック) → 販売(成約/CVR) → 定着(継続率)
2. 前層比で最も落ちている段 = 穴。そこだけを直す施策を1つ打つ
3. 数字がない層があれば、それが最初の穴（未計測 = 見えない穴。os-forge.md §4）
```

- 穴は同時に1つずつ塞ぐ。全層同時改修は効果の切り分けができず、学びが残らない。
- よくある誤診: 「販売が弱い」と見えて実は教育量が不足（オファー時点で信頼残高ゼロ）。販売CVRが低いときは、まず教育層の接触回数・期間を確認する。

## §4 設計の5原則

1. **規約の内側で自動化する** — エンゲージメント操作・報酬付き拡散などプラットフォーム規約に反する成長装置は組み込まない。アカウント凍結は資産没収である（place.md §2）
2. **文章の正典は人が書く** — 導線の自動化と原稿の自動生成を混同しない（原稿は人・OSは増幅）
3. **広告費ゼロを基本形とする** — オーガニック（アルゴリズム・SEO・紹介制度）で環を閉じる設計を先に作る。広告は環が閉じた後の増幅器
4. **規約と法令の両面を満たす** — 片方だけ見て設計しない（review-protocol.md §4）
5. **プライバシーの既定を守る** — 計測は匿名・集計を基本とし、新規ツール導入で既存の水準を下げない

## §5 道具箱（名前つきフレームワーク・出典つき）

道具の使い方の掟は positioning.md §6 冒頭と同じ（名前は索引・不正確に引かない）。

- **AARRR（海賊指標）**（Dave McClure）: Acquisition／Activation／Retention／Referral／Revenue。§1の5層と同型の古典で、KPIツリー（os-forge.md §4）のカテゴリ分けの系譜元。
  **明鏡の目**: 頭文字より順序が本体。Referralが弱いのはたいてい、定着＝仲間化（柱5）を飛ばして拡散だけ欲しがっているからである。
- **グロースループ**（Reforge）: 「ファネルは漏斗でなく環」という§2と同じ思想の英語圏標準形。近年の合意は「ファネルとループの併用」——どちらか一方主義に付き合う必要はない。
  **明鏡の目**: 環を閉じる最後の一辺は仕組みではなく文化（柱6）。紹介報酬だけで閉じた環は、報酬が切れた瞬間に開く。
- **Core Four ＋ Rule of 100**（Alex Hormozi『$100M Leads』）: 集客経路は「温かい接触／コンテンツ／冷たい接触／広告」の4つだけ。選んだ1つを毎日100回・90日続けてから次を語る——柱3（基準値）の英語圏版。
  **明鏡の目**: 毎日100回は根性ではなく仕組みで達成する。人力で維持できる基準値は基準値ではない（→ automation.md）。
- **ICE優先順位づけ**（Julian Shapiro）: 施策候補を Impact／Confidence／Ease で採点して並べる。候補が多くて選べないとき（kaizen.md の提案3件を絞るとき）の物差し。
  **明鏡の目**: Easeに引かれて易きに流れるのはAIの癖でもある。採点の前に、Impactの根拠に台帳の実数があるか（根拠の掟）を問う。
- **チャネル2軸評価（著者の実戦から）**: 各流入チャネルを「到達率（CTAクリック→LP到着）」と「転換率（LP到着→登録/購入）」の2軸に分けて評価する。到達率が高くて転換率が低い媒体は「送り出しは強いが刺さっていない」、逆は「刺さるが届いていない」——著者の実運用では媒体間で転換率に**10倍近い差**が出た実測がある（2026年）。処方も逆になる: 前者はCTA前の接続文を、後者は導線の露出を直す。転換率最良の媒体の接続文を他媒体へ横展開すると、全体CVRの底上げになる。
