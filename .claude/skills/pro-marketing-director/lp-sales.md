# lp-sales.md — LP・セールスコピー・ローンチ

転換点（LP・セールスレター・ローンチ）の制作すべてで読む。ここはファネルの販売層＝**信頼残高を成果に変える現場**であり、同時に法的リスクが最も集中する場所。出荷前のリーガル検品（review-protocol.md §4）は絶対に飛ばさない。

## §1 コピーの原材料は3つだけ

1. **変化の一文**（positioning.md）— 何が変わるのか
2. **部族の言葉**（research-protocol.md §2 の生の声）— 悩みと欲求を、部族自身の語彙で
3. **事実台帳**（os-forge.md §5）— 使ってよい実績・証言・数字

この3つの外から言葉を持ってこない。台帳にない実績を「それらしく」書いた時点で事実検品落ち。**うまいコピーとは修辞ではなく、正しい証拠の正しい順番である。**

## §2 LPの基本構造

```
1. ヒーロー: 変化の一文 + 一枚画像/動画。3秒で「自分向けだ」と分かるか
2. 共感: 部族の現状の言語化（生の声の語彙で）。「私のことだ」を作る
3. 証拠: 実績・証言・デモ。主張1つに証拠1つ
4. オファー: 内容・価格・特典・保証・期限（offer-design.md §6 の掟に従う）
5. FAQ: 断られた理由（実売テストの記録）への先回り回答
6. CTA: 行動は1種類。迷いの数だけCVRは下がる
7. 法定表示: 特商法表記・返金条件への導線
```

- 証言は実在のもののみ、掲載許可を取り、代表性に注意する（例外的な成功例を「誰でもこうなる」ように見せない——景表法の体験談規制）。
- 打消し表示（※注釈）を小さく隠さない。読めない注釈は法的にも信頼的にも逆効果。

## §3 セールスレターの型

```
問題提起（部族の言葉で）→ 変化の提示 → なぜ可能か（方法の骨子）
→ 証拠 → オファー → 希少性/期限（実態のあるもののみ）→ CTA → 追伸（最重要の一点を再掲）
```

- 希少性は**嘘のないものだけ**使う: 実在の定員・実在の締切・予告済みの値上げ（offer-design.md §4）。演出の「残りわずか」はリーガル検品で落ちる。
- 長さは信頼残高に反比例させる。教育（mail.md）が効いている読者には短く、初見の読者には証拠を厚く。

## §4 ローンチの型

販売を「点」でなく「祭りの期間」として設計する:

```
準備   : 事実台帳の整備・LP完成・検品4種通過・計測の設営（どのリンクから買われたか追えるか）
予告   : 発売日と価格を事前に告知。値上げ/締切があるなら根拠と共に予告
開演   : 初日に最大熱量（ライブ・記念コンテンツ）。買った人の声を（許可を得て）即時に流す
中盤   : FAQ・不安への回答・事例の追加投下。売り込みの連打ではなく「迷いの解消」を投下する
締切   : 予告した通りに締める。締切後に「延長」を乱発しない——次回の締切が全部嘘になる
事後   : 購入者を定着へ（community.md）。買わなかった人には感謝と次の予告。数字の振り返りを決定ログへ
```

- ローンチ全体が1つのKPI宣言（動かすKPI=販売数/売上）＋期間中の各投下物が個別の検品対象。
- 記念・感謝の回とセールスの回は分ける（mail.md の掟と同じ。感謝が営業に見えた瞬間、信頼が減る）。

## §5 計測

- LPのCVR（訪問→購入 or 訪問→登録）を必ず計測する。計測できないLPは公開しない（見えない穴。funnel.md §3）。
- 流入元別のCVRが取れると、どのチャネルの部族が濃いかが分かる（チャネル方針表の更新材料）。
- 改善は1要素ずつ（ヒーロー文言→証拠の順が定石）。同時に複数変えるとどれが効いたか永久に分からない。

## §6 道具箱（名前つきフレームワーク・出典つき）

道具の使い方の掟は positioning.md §6 冒頭と同じ（名前は索引・不正確に引かない）。

- **StoryBrand 7部構成**（Donald Miller）: 主人公=顧客／課題／導き手=あなた／計画／行動喚起／回避される失敗／得られる成功。§2LP構造の物語版で、**「LPの主役は売り手ではなく顧客」**という視点の矯正具として優秀。ヒーローセクションが自分語りになっていたらこれで直す。
  **明鏡の目**: 導き手の資格は物語の型ではなく実体験の証拠（柱1）。証拠が事実台帳になければ、どれほど美しい脚本もただの脚本である。
