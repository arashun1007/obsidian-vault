# offer-design.md — 商品ラダーと価格戦略（Product × Price）

商品設計・値付け・値上げ・オファー変更のとき読む。このモジュールの出力はすべて**戦略宣言**（core.md §4）として書き、**最終決定は必ず人間が行う**。値決めは経営である。AIの仕事は選択肢×試算×リスクの裁定資料まで。

## §1 本命逆算（明鏡・柱7）

商品設計は本命（バックエンド）から逆算する。フロントから積み上げない。

```
1. 本命を決める: 高単価×少数。部族の変化を最後まで届ける商品
2. 本命が売れるために必要な信頼・教育を洗い出す
3. それを供給するミドル・フロント・無料コンテンツを逆算で配置する
```

- 「高単価を少数に」が基本形である理由: 低単価×多数は個人の体力では回らず、サポート品質が落ちて旗（positioning.md）が毀損する。少数の深い変化のほうが証言（証拠資産）も生まれやすい。
- 本命が決まっていない状態でフロント商品を乱発しない。導線の行き先がないフロントは、穴の開いたバケツに水を注ぐ行為（柱2）。

## §2 商品ラダー

```
無料     : 発信・無料プレゼント（リスト取得）— 価値の証明
フロント : 低単価の買いやすい入口 — 「財布を開く」体験の提供
ミドル   : 中単価 — 本命の前段の変化
本命     : 高単価 — 部族の変化の完成
継続     : サブスク/コミュニティ — 定着と文化（community.md）
```

- 各段の役割は**上の段への信頼供給**。段の中で完結して満足させつつ、次の変化の存在を示す。
- 全段を最初から作らない。P0（core.md §3）は「無料＋本命」の2段で打席に立ち、売れてから間を埋める。

## §3 課金形態の裁定表

| 形態 | 向く条件 | リスク |
|---|---|---|
| 買い切り | 完結する変化・教材型 | LTVが1回で頭打ち。値上げでしか伸びない |
| サブスク | 継続供給できる価値がある場合のみ | 供給が止まると解約の雪崩。「回収装置」化すると文化が死ぬ（柱6） |
| 支援パス型（応援課金） | 無料で成立している本体＋応援したい部族 | 対価性が薄いぶん、部族の熱量に完全依存 |
| 教材＋雛形/ツール同梱 | 知識だけでは実行できない領域 | 雛形のメンテ義務を負う。更新方針を先に決める |

## §4 値付けと値上げの型

- **アンカリングは合法の範囲で**: 比較対象（上位プラン・他の手段のコスト）を示すのは正当。**虚偽の元値・実態のない割引は景品表示法の二重価格表示**であり、リーガル検品（review-protocol.md §4）で必ず落とす。
- **段階値上げの型**: 価格は受講者数・実績の蓄積とともに段階的に上げる。値上げの**事前予告**は、既存検討者への誠実さと正当な緊急性の両方を兼ねる、数少ない「嘘のない希少性」である。
  - 予告→猶予期間→実行、を必ずセットにする。予告なしの値上げは検討中の部族への裏切りに映る。
  - 「値上げします」と言ったら必ず上げる。上げない値上げ予告は一度で信用を破壊する（実態と表示の一致。リーガル検品対象）。
  - 既存購入者の扱い（据え置き/追加特典）を値上げ宣言に必ず含める。
- **値下げは最後の手段**: 既存購入者の体験を毀損し、旗の価値を下げる。売れないときはまず価格ではなくファネルの穴（funnel.md）とオファーの証拠不足を疑う。

## §5 試算の型（戦略宣言の「試算」欄に書くもの）

```
- 粗利/件 = 価格 − 直接コスト（決済手数料・販路手数料 place.md 参照）
- LTV = 粗利/件 × 平均購入回数（サブスクは 月額粗利 ÷ 月次解約率）
- 許容CAC < LTV × 1/3 を目安（広告費ゼロ方針でも、制作時間を時給換算して入れる）
- 損益分岐: 固定コスト ÷ 粗利/件 = 必要販売数 → 現実のリスト規模×想定CVRで届くか
```

概算でよいが**式を書く**。式のない試算は試算ではなく願望である。

## §6 オファー文の掟

- オファー（提供内容・価格・期限・特典・保証）は**事実台帳**（os-forge.md §5）に登録された事実のみで構成する。台帳にない実績・証言・効果を書かない（事実検品の対象）。
- 期限・限定数は実態と一致させる。「演出の残りわずか」は書いた時点で違法リスク（景表法）。
- 返金・解約条件は隠さず書く。条件明示は特商法の義務であると同時に、購入の心理障壁を下げるオファーの一部である。

## §7 道具箱（名前つきフレームワーク・出典つき）

道具の使い方の掟は positioning.md §6 冒頭と同じ（名前は索引・不正確に引かない）。

- **価値の方程式**（Alex Hormozi『$100M Offers』）: 価値 =（夢の成果 × 達成可能性の実感）÷（時間の遅れ × 労力）。オファーを磨く4レバーの点検表——**価格を下げる前に分母（遅れ・労力）を削れ**、が実務上の要点。
  **明鏡の目**: 方程式は、欲しくないものを磨けない。分母を削る前に、分子が「あなた自身が人生を賭けても欲しい変化」か（柱1）。
- **バリューラダー**（Russell Brunson『DotCom Secrets』）: §2商品ラダーの系譜元。無料→フロント→本命→継続の段設計。
  **明鏡の目**: 段は信頼の供給路であって陳列棚ではない。段を増やすこと自体が目的化したら柱7違反——P0は無料＋本命の2段でよい。
- **ステアステップ法**（Rob Walling）: いきなり本命サブスクを狙わず、①買い切りの小さな一勝→②その反復→③本命、と段を登る個人事業者向けの順路。P0〜P1でどの商品から作るかの参考。
  **明鏡の目**: 小さな一勝は打席（柱7）の実装。ただし一勝ごとに旗（positioning.md）がブレていないか点検する——階段は一本の旗の下に架ける。
