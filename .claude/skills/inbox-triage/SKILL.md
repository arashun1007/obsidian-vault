# inbox-triage — 00_inbox の週次整理

## 大原則

- **削除は絶対にしない。** 不要そうなメモも「アーカイブ候補」として提案するだけ。
- **移動・改名は承認制。** 提案一覧を出し、本人が「OK」「1と3だけ」など承認した分だけ実行する。
- 中身の書き換えはしない(改名と移動のみ)。

## 手順

### 1. 読む
`00_inbox/` の全ファイルと、`90_meta/SOP/ファイル命名ルール.md` の分類表。

### 2. 分類を提案する

各ファイルについて、中身を読んで以下の表形式で提案する。

```
| # | 現ファイル名 | 内容の要約(一行) | 提案先 | 提案ファイル名 |
|---|---|---|---|---|
```

判断基準:
- 日記の断片 → `01_daily/YYYY/MM/` の該当日(既存日記がある日は「既存日記への追記候補」として本文を提示するだけ。勝手にマージしない)
- 観察・ネタ → `30_publish/Substack/素材/YYYY-MM-DD_ひとこと.md`
- 仕事メモ → `10_work/`
- 概念・学び → `20_knowledge/`
- 判断がつかないもの → 「要相談」と明記して本人に聞く

### 3. 承認された分だけ実行する
`git mv` 相当の移動(Bashの`mv`)を実行し、実行結果を一覧で報告する。
承認されなかったものは inbox に残す。

### 4. 報告
移動した件数、残った件数、要相談の件数を報告して終わる。
